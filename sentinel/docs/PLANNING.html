00 / 한 줄 요약

무엇을 만드는가

태블릿은 기본적으로 잠긴 벽돌 상태다. 관리자(나)가 지문으로 열고 "30분" 같은 사용 시간을 부여할 때만 살아나고, 그 시간 동안 태블릿이 무엇을 했는지 전부 기록한다. 콘텐츠 자체는 막지 않는다 — 통제는 사후에 로그를 보고 내가 한다.

두 개의 앱으로 구성된다. 태블릿 앱(Master)은 모든 설정·잠금·활성화·기록을 담당하고, 휴대폰 앱(Monitor)은 읽기 전용으로 상태를 보고 로그를 뽑는다. 둘은 내 소유임을 증명하는 방식으로 바인딩된다.

설계 철학 막는 게 아니라 기록한다. 차단 규칙을 끝없이 관리하는 대신, 완전한 사용 로그를 남겨 사후 통제의 근거로 삼는다. 유일하게 강제하는 것은 "언제 얼마나 켤 수 있는가" 하나뿐이다.
01 / 핵심 흐름

실행부터 종료까지

네가 그린 뼈대를 상태 전이로 다시 정리했어. 태블릿은 항상 세 상태 중 하나에 있어: LOCKED ACTIVE EXPIRED.

1
부팅 & 상시 잠금 (LOCKED)
태블릿이 켜지면 Sentinel이 자동 실행되어 전체화면 잠금(키오스크)을 건다. 홈·최근앱·상태바가 죽고 다른 앱으로 못 나간다. 이게 기본값 — 아무 부여가 없으면 벽돌.
2
관리자 지문 인증
잠금 화면의 "관리자" 버튼 → 지문만 요구(패턴/PIN 폴백 없음, §2 참고). 통과하면 관리자 콘솔이 열린다. 오직 태블릿에서만 가능.
3
사용 시간 부여
콘솔에서 활성화 시간을 입력 예: 30분. (선택) 이번 세션에 허용/차단할 앱 프로필도 고를 수 있게 확장 가능.
4
활성화 확정 → 사용 개시 (ACTIVE)
지문 재인증 또는 안드로이드 잠금과 다른 별도 앱 PW 입력으로 확정. 이 순간부터 키오스크가 풀리고 카운트다운 시작. Sentinel은 백그라운드에서 모든 활동을 기록하기 시작한다.
5
시간 만료 → 재잠금 (EXPIRED → LOCKED)
타이머 0 → 즉시 키오스크 복귀. 화면 상단에 남은 시간 표시(HUD), 만료 임박 시 경고. 세션 요약 로그가 확정 저장·동기화된다.
6
앱 종료 = 별도 PW
Sentinel 자체를 끄거나 설정을 바꾸는 것도 별도 PW를 요구. Device Owner라 강제 종료·삭제·초기화가 막혀 있어서 우회가 어렵다.
추가 제안 — 스케줄 & 예산 매번 수동 부여가 번거로우면, "평일 저녁 19–20시만 자동 허용", "하루 총 90분 예산" 같은 규칙 기반 자동 부여를 나중에 얹을 수 있어(M4). 뼈대엔 없던 거라 옵션으로 남겨둠.
02 / 인증 설계

지문만, 패턴은 배제 — 가능한가?

결론: 가능하다. 다만 "지문"과 "얼굴"을 앱이 강제로 구분하는 건 API의 회색지대라 짚고 넘어가자.

패턴/PIN 배제 — 확실히 됨

BiometricPrompt를 setAllowedAuthenticators(BIOMETRIC_STRONG)로 호출하면 생체인증만 받고, 안드로이드 잠금(패턴·PIN·비밀번호)으로의 폴백이 발생하지 않는다. 즉 네가 원한 "패턴 안 됨"은 API 차원에서 보장돼.

지문 vs 얼굴

안드로이드는 앱에 "지문만"이라고 직접 지정하는 공개 API를 주지 않는다. 대신 생체 등급으로 갈린다: Tab S10 Ultra의 초음파 지문은 Class 3(STRONG), 얼굴 인식은 통상 Class 2(WEAK)다. 그래서 BIOMETRIC_STRONG만 허용하면 얼굴은 자동 배제되고 사실상 지문만 남을 가능성이 크다. (기기 펌웨어의 등급 분류에 의존하므로 실기로 1회 검증 필요.)

3중 인증 게이트

관문수단용도
콘솔 진입지문(STRONG)관리자만 설정 화면 접근
활성화 확정지문 또는 별도 PW사용 시간 개시 승인
종료·설정변경별도 PW앱 우회·무력화 방지

별도 PW는 안드로이드 기기 잠금과 완전히 별개다. 앱 내부에서 Argon2/PBKDF2로 해시하여 저장하고, 원문은 어디에도 보관하지 않는다. 지문 하드웨어가 실패할 때의 백업 경로 역할도 겸한다.

03 / 기기 바인딩

내 폰과 태블릿만 연결

"내 소유"를 증명하는 2단계. soft(계정)로 편의성, hard(기기 지문)로 위조 방지를 병행한다.

  • Soft — Google 계정: 폰·태블릿 모두 같은 Google 계정으로 Firebase Auth 로그인. 페어링의 1차 신뢰 축.
  • Hard — 기기 식별자 바인딩: 최초 페어링 시 태블릿이 QR(일회용 토큰)을 띄우고 폰이 스캔 → 서로의 기기 지문을 교환·고정한다. Android 10부터 Wi-Fi MAC이 랜덤화/접근 제한되므로 MAC 대신 Settings.Secure.ANDROID_ID + 앱 설치 인스턴스 ID(FCM 토큰 기반) + Play Integrity 신호를 조합한 지문을 쓴다.
  • 화이트리스트: 태블릿은 바인딩된 폰 인스턴스 ID 목록만 모니터로 인정. 새 기기가 붙으려면 태블릿에서 지문 인증 후 승인해야 한다.
현실 체크 — MAC 주소 네가 언급한 MAC 하드 바인딩은 방향은 맞지만, 최신 안드로이드에선 앱이 하드웨어 MAC을 못 읽어(랜덤화·권한 차단). 그래서 기능적으로 동등한 기기 지문 조합으로 대체하자 — 목적(위조 방지)은 그대로 달성돼.
04 / 강제력

Device Owner로 "사용불가"를 진짜로 만든다

일반 앱 권한으론 사용자가 홈 버튼 한 번으로 빠져나간다. Device Owner(기기 소유자)는 그걸 원천 봉쇄한다 — 통제 목적엔 이게 정답.

세팅 방법 (최초 1회, ADB)

계정이 하나도 없는 상태여야 소유자 지정이 된다. 순서:

  • 태블릿 공장초기화 → 아무 계정도 추가하지 않고 통과
  • Sentinel APK 설치 후 PC에서
    adb shell dpm set-device-owner com.sentinel/.AdminReceiver
  • 그 다음 Google 계정 로그인(§3 바인딩용). 소유자 지정은 이미 끝나 영향 없음.

한 번 지정되면 앱 삭제·강제종료·데이터 초기화가 막히고, 우회하려면 다시 공장초기화(=모든 데이터 소멸)밖에 없다.

05 / 모니터링 & 로깅

기록은 어디까지 되나 (정직하게)

"모든 것을 기록"의 현실적 경계를 먼저 못 박자. 앱 단위 활동은 완벽히 잡히지만, 화면 안의 콘텐츠(어떤 영상·어떤 웹페이지)는 기본 API로는 안 잡힌다.

콘텐츠 로깅 — 2트랙 전략

"어떤 웹/영상/방인지"는 잡히는 정도가 앱마다 극단적으로 갈린다. 그래서 한 방식으로 뭉뚱그리지 않고 둘로 나눈다.

트랙 A 텍스트로 잡히는 것 — Accessibility 콘텐츠 모듈

네이티브 뷰라 화면에 텍스트가 떠 있는 앱은 a11y 트리에서 긁는다. 웹 URL, 유튜브 채널명·제목이 여기 해당. 앱별 셀렉터 규칙을 두고, UI가 바뀌면 규칙만 갱신한다. (M3~M4)

트랙 B 게임처럼 안 잡히는 것 — 앱·세션 단위 + 옵트인 캡처

로블록스는 화면 전체가 GL 서피스라 방 이름 같은 내부 텍스트가 a11y에 아예 안 뜬다. 기본은 "로블록스 몇 분 실행"까지만 기록. 정말 안을 봐야 하면, 지정한 앱에 한해서만 N초 간격 스크린샷을 남겨 사후 확인하는 옵트인 옵션을 별도로 둔다(평소엔 OFF, 배터리·저장 부담 인지하고 사용).

신뢰도 주의 트랙 A는 대상 앱(유튜브 등)이 레이아웃을 바꾸면 규칙이 깨질 수 있어 유지보수가 따른다. 이건 우리 앱의 한계가 아니라 이 방식 전체의 태생적 제약 — 시중 통제 앱들도 똑같이 겪는다.

수집 파이프라인

  • Foreground Service가 ACTIVE 동안 상주하며 이벤트를 폴링·구독한다.
  • 로컬 우선: Room DB에 먼저 append(오프라인·비행기모드에도 유실 없음).
  • 주기적으로 Firestore에 배치 업로드. 폰이 실시간 모드면 즉시, 절전 모드면 N분 간격 동기화.
  • 로그 추출: 폰 앱에서 기간 선택 → CSV/JSON 내보내기(공유 시트로 저장·전송).
네 방침 — 실시간 차단 안 함 성인물 등 이상 콘텐츠를 봐도 세션 중엔 막지 않는다. 무한 트래킹·규칙 관리가 비현실적이라는 판단에 동의. Sentinel은 완전한 로그만 남기고, 판단·통제는 사후에 네가 로그를 보고 한다.
06 / 휴대폰 앱 (Monitor)

읽기 전용 관제탑

설정 권한은 0. 오직 보고 뽑기만 한다.

  • 현재 상태 카드: 태블릿이 지금 LOCKED인지 ACTIVE인지, 화면 켜짐/잠금해제 여부, 남은 시간, 현재 실행 중인 앱.
  • 동기화 모드 토글: 실시간(FCM 푸시 구독) ↔ 절전(주기 폴링). 폰에서 켠다.
  • 세션 히스토리: 지난 세션들의 타임라인·앱별 사용시간·잠금해제 횟수.
  • 로그 추출: 기간 지정 CSV/JSON 다운로드.
  • 알림(선택): "태블릿 활성화됨", "세션 만료", "미등록 기기 페어링 시도" 등 FCM 푸시.
07 / 데이터 모델

Firestore 구조 (초안)

/owners/{uid}
  ├─ devices/{deviceId}          // 바인딩된 태블릿·폰
  │    ├─ role: "master" | "monitor"
  │    ├─ instanceId, fingerprint     // 하드 바인딩 지문
  │    └─ boundAt, lastSeen
  │
  ├─ liveState/{tabletId}        // 실시간 1문서, 계속 덮어씀
  │    ├─ status: LOCKED|ACTIVE|EXPIRED
  │    ├─ screenOn, unlocked
  │    ├─ sessionEndsAt               // 남은시간 계산용
  │    └─ currentApp, updatedAt
  │
  └─ sessions/{sessionId}       // 부여~만료 1세션
       ├─ grantedMinutes, startedAt, endedAt
       ├─ approvedBy: "fingerprint"|"password"
       └─ events/{eventId}       // append-only 로그
            ├─ ts, type: APP_FG|UNLOCK|SCREEN_OFF|...
            ├─ package, appLabel
            └─ durationMs

보안 규칙: 문서는 소유자 uid 본인만 read. 쓰기는 태블릿(master)만, 폰(monitor)은 read-only로 규칙에서 강제.

10 / 확정된 결정

정해진 것 (v0.2)

D1 · 콘텐츠 로깅 — 채택 앱 단위를 넘어 웹 URL·유튜브 채널명/제목까지 잡는다(트랙 A). 로블록스 등 게임은 앱·세션 단위 + 옵트인 캡처(트랙 B). §5 2트랙 전략대로.
D2 · ADB 세팅 — 가능(나중) 공장초기화+adb 환경 확보돼 있음. 당장은 아니어도 됨 → 개발은 일반 설치로 진행하고, Device Owner 실기 검증은 준비되는 시점에.
D3 · 부여 방식 — 수동 기본 + 자동 구현 실사용은 수동 부여로. 단 자동 스케줄/일일예산 기능은 구현해 둔다(기본 비활성, 필요 시 켬).
D4 · 이름 — Sentinel 확정 🛡️ 패키지 com.sentinel 기준으로 스캐폴딩.

다음 스텝

M0(스캐폴딩) + M1(코어 잠금 루프) 착수. Firebase 프로젝트의 google-services.json은 네가 콘솔에서 만들어 넣어주면 되고(그 전까진 플레이스홀더로 진행), Device Owner 실기 검증은 D2 시점에 맞춰서.
