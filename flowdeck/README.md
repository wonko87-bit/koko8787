# Flowdeck

윈도우 11 바탕화면에 상주하면서 **자연어 한 줄로 할일과 일정을 동시에 기록**하는 업무환경 앱입니다.

- 바탕화면 위젯: 달력 + 오늘의 일정 + 할일을 한 화면에
- 전역 단축키(`Ctrl+Alt+Space`)로 어디서든 뜨는 입력창
- `내일 오후 3시 팀 회의` 처럼 그냥 쓰면 알아서 날짜·시간·반복·태그를 뽑아냄
- `!TD` / `!CD` 로 할일과 일정을 골라서 저장, 표기가 없으면 양쪽 모두
- `!OL` 로 Outlook에 복사, `!TM` 으로 Teams 회의 폼 열기 — 둘 다 권한·승인 없이
- 흑백/회색조 전용 디자인 (다크 · 라이트)

---

## 1. 기술 선택

**C# / .NET 8** 을 골랐습니다. 요구사항이 "윈도우에 가장 적합하면서 모바일 확장도 쉬울 것"이었고, 이 조합이 두 조건을 동시에 만족하는 유일한 선택지에 가깝습니다.

| | 이유 |
|---|---|
| **데스크톱: WPF** | 바탕화면 위젯에 필요한 것들(테두리 없는 반투명 창, z-order 고정, Alt+Tab 제외, 전역 단축키 `RegisterHotKey`, 트레이 아이콘, 시작 프로그램 등록)이 전부 Win32 API 직결입니다. Electron·Flutter는 이걸 전부 플러그인/네이티브 셰임을 거쳐야 하고, WinUI 3는 패키징 제약이 더 큽니다. |
| **모바일: .NET MAUI** | 파서·저장·반복 규칙 등 앱의 핵심 로직이 전부 `Flowdeck.Core` 한 어셈블리에 있고, 이 어셈블리는 플랫폼 의존성이 **0** 입니다. MAUI는 `net8.0-android` / `net8.0-ios` 를 타깃하며 `net8.0` 라이브러리를 그대로 참조합니다. 즉 안드로이드·아이폰으로 갈 때 **다시 짜야 하는 건 화면뿐**입니다. |
| **의존성** | 외부 NuGet 패키지를 하나도 쓰지 않습니다. 저장은 `System.Text.Json`, 변경 알림은 직접 구현. 오프라인에서도 복원·빌드됩니다. |

구조상 경계가 이렇게 잡혀 있습니다.

```
Flowdeck.Core      ← 플랫폼 무관. 파서 / 분류 / 저장 / 반복 / ICS 내보내기
   ↑           ↑
WPF (지금)   MAUI (나중)   ← 화면만 각자
```

## 2. 빌드와 실행

필요한 것: **Windows 10 1809 이상**(권장 Windows 11), [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)

```powershell
cd flowdeck
dotnet run --project src/Flowdeck.Windows
```

배포용 실행 파일:

```powershell
dotnet publish src/Flowdeck.Windows -c Release -r win-x64 --self-contained false -o publish
.\publish\Flowdeck.exe
```

.NET 런타임 없이 단독 실행되게 하려면 `--self-contained true` 로 바꾸면 됩니다(용량은 커집니다).

실행하면 창이 뜨는 대신 **트레이 아이콘**이 생기고 바탕화면에 위젯이 나타납니다. 트레이 아이콘을 더블클릭하면 위젯이 켜지고 꺼집니다.

## 3. 입력 문법

입력창에 문장을 그대로 쓰면 됩니다. 인식된 부분은 제목에서 빠지고 나머지가 제목이 됩니다.

### 3.1 할일 / 일정 구분 — 지정된 문구

우선순위가 높은 것부터 적용됩니다.

**① 표기(marker) — 문장 맨 앞이나 맨 뒤**

| 저장 위치 | 쓸 수 있는 표기 |
|---|---|
| **할일만** | `!TD` · `!todo` · `!할일` · `!투두` · `/t` · `할일` · `투두` · `todo` |
| **달력만** | `!CD` · `!cal` · `!일정` · `!캘` · `/c` · `일정` · `캘린더` · `달력` |
| **양쪽 모두** | `!BD` · `!both` · `!둘다` · `!모두` · `/b` · `둘다` |

대소문자는 가리지 않습니다. 표기는 **단독 낱말로 맨 앞이나 맨 뒤에 있을 때만** 인식합니다. 그래서 `일정관리 앱 알아보기` 는 표기로 오인되지 않고 제목 그대로 남습니다.

```
!TD 내일 오후 9시 운동        → 할일에만.  "운동", 내일 21:00 마감
!CD 내일 업무보고회의          → 달력에만.  "업무보고회의", 내일 종일
내일 오후 3시 스터디 할일       → 할일에만  (맨 뒤 표기)
```

> **`!OL` 과 `!TM` 은 이 표와 다른 축입니다.** 할일이냐 일정이냐를 정하는 게 아니라 각각 **Outlook에도 보낼지**, **Teams 회의 폼을 열지**를 정합니다. 그래서 위 표기와 같이 씁니다 — 자세한 건 [8. Outlook 연동](#8-outlook-연동)과 [9. Teams 회의 잡기](#9-teams-회의-잡기).

**② 해시태그 — 문장 아무 데나**

`#할일` `#투두` `#todo` `#td` → 할일만 / `#일정` `#캘린더` `#cal` `#cd` → 달력만

**③ 낱말 자동 분류** (설정에서 끌 수 있음)

표기가 하나도 없으면 아래 낱말을 훑어봅니다.

| | 낱말 |
|---|---|
| **달력 쪽** | 회의, 미팅, 약속, 세미나, 워크샵, 워크숍, 면담, 인터뷰, 면접, 발표, 행사, 출장, 강의, 수업, 진료, 예약, 컨퍼런스, 브리핑, 회식, 점심, 저녁식사, 생일, 기념일, 휴가, 연차, 반차, meeting, appointment, call, party |
| **할일 쪽** | 제출, 작성, 정리, 확인, 검토, 구매, 구입, 결제, 신청, 등록, 처리, 마감, 준비, 예습, 복습, 청소, 빨래, 설거지, 전화하기, 보내기, 답장, 회신, 리뷰, 수정, 배포, 테스트, 버그, 사기, 읽기, 쓰기, 챙기기, todo |

한쪽만 걸리면 그쪽으로, **양쪽 다 걸리거나 아무것도 안 걸리면 양쪽 모두**에 저장합니다.

```
내일 오후 3시 팀 회의     → 달력만   ("회의")
금요일까지 보고서 제출     → 할일만   ("제출")
회의 자료 작성           → 양쪽 모두 (양쪽 낱말이 다 걸림)
내일 오후 9시 운동        → 양쪽 모두 (아무것도 안 걸림 = 기본값)
```

낱말 목록은 `%APPDATA%\Flowdeck\settings.json` 의 `Routing.CalendarKeywords` / `Routing.TodoKeywords` 에서 직접 고칠 수 있습니다.

**④ 기본 분류를 아예 정해두기**

낱말 추정이 부담스럽거나, 애초에 한쪽만 쓰는 사람이라면 **설정 → 입력 해석 → "표기가 없을 때 기본 분류"** 에서 넷 중 하나를 고르면 됩니다.

| 고르는 값 | 표기가 없는 입력이 가는 곳 |
|---|---|
| **자동** | 위 ③번 낱말 추정 (기본값) |
| **할일** | 항상 할일로 |
| **일정** | 항상 일정으로 |
| **둘 다** | 항상 양쪽 모두 |

`자동` 말고 아무거나 고르면 **낱말 추정은 완전히 꺼집니다.** "전부 할일로" 라고 해놓고 `회의` 라는 낱말 하나 때문에 일정으로 새는 게 더 당황스럽기 때문입니다.

정해둔 뒤에도 **예외는 그때그때** 만들 수 있습니다 — `!TD` / `!CD` / `!BD` 를 붙이거나, 빠른 입력창에서 `Ctrl`+`1` / `2` / `3`. 같은 키를 한 번 더 누르면 예외가 풀리고 기본값으로 돌아갑니다.

이 설정은 `!OL` 과 짝지어 쓰면 **"내 사용 모드"** 가 됩니다. 예를 들어 기본 분류를 `할일`, Outlook을 "항상 저장"으로 켜두면 그냥 쳐도 매번 `!OL !TD` 를 친 것과 같고, 회의 하나 잡을 때만 `Ctrl`+`2` 를 누르면 됩니다.

> **날짜가 없는 입력은 할일로만 갑니다.** `영수증 정리` 처럼 언제인지가 없으면 달력에 그릴 자리가 없기 때문입니다. 양쪽 모두로 분류되더라도 할일 하나만 만들어집니다.

### 3.2 날짜

```
오늘 · 내일 · 모레 · 글피 · 어제
3일 후 · 2주 후
월요일 … 일요일                    (오늘 포함, 다가오는 요일)
이번주 금요일 · 다음주 월요일 · 다다음주 화요일
이번달 5일 · 다음달 5일
주말 · 다음 주말                    (그 주 토요일)
8월 12일 · 12일 · 9/15 · 2026-08-12
```

`8월 12일` 처럼 올해 날짜가 이미 지났으면 내년으로, `12일` 처럼 이번 달 날짜가 지났으면 다음 달로 넘깁니다.

### 3.3 시간

```
오전 9시 · 오후 3시 · 오후 3시 30분 · 오후 3시 반
새벽 5시 · 아침 8시 · 점심 · 저녁 7시 · 밤 11시 · 정오 · 자정
14:30 · 9:15am · 8pm
```

**오전/오후 표기가 없는 1~7시는 오후로 읽습니다.** `내일 3시 회의` → 15:00. `9시`처럼 8시 이상은 그대로 오전입니다. 이 규칙은 설정에서 끌 수 있고, 끄면 `3시`는 03:00이 됩니다. `오전 3시` 처럼 명시하면 언제나 그대로입니다.

날짜 없이 시간만 쓰면 오늘로 잡되, 이미 지난 시각이면 내일로 넘깁니다.

### 3.4 구간과 길이

```
내일 오후 3시~5시              → 15:00 – 17:00
내일 오전 10시부터 오후 1시까지  → 10:00 – 13:00
내일 오전 10시~1시             → 10:00 – 13:00   (뒤 시각은 앞 시각과 같은 오전/오후로)
8월 10일 ~ 8월 12일            → 종일 3일짜리
내일 오후 2시 2시간             → 14:00 – 16:00
내일 오후 2시 30분간            → 14:00 – 14:30
```

시간만 있고 끝이 없으면 1시간짜리로 잡습니다.

### 3.5 반복 · 우선순위 · 태그 · 알림

```
매일 · 평일 · 매주 · 격주 · 매월 · 매년 · 3일마다 · 2주마다
매주 화요일 오전 10시 주간회의    → 매주 화요일 반복

!1 !2 !3 !4                    → 우선순위 (1이 가장 급함)
긴급 · 중요                     → 우선순위를 올리되 제목에는 그대로 남음

#업무 #개인                     → 태그

30분 전 알림 · 1시간 전 알림      → 트레이 알림

/* 뒤로는 전부 메모                → 메모 (\n 으로 줄바꿈)
```

### 메모

`/*` 뒤에 쓴 것은 **전부 메모**가 됩니다. 메모 안은 해석하지 않으므로, 날짜나 `#` 이 들어 있어도 일정이 옮겨가거나 태그가 붙지 않습니다.

```
!TD 금요일까지 보고서 제출 /* 3장부터 다시 검토\n팀장님 코멘트 반영
```

- 줄바꿈은 **`\n`** 으로 씁니다. 위 예시는 두 줄짜리 메모가 됩니다.
- **`*/` 는 안 닫아도 됩니다.** 안 닫으면 줄 끝까지가 메모입니다. 보통은 이렇게 씁니다.
- 닫으면 그 뒤는 다시 평소대로 읽습니다. 메모를 가운데 넣고 일정을 뒤에 쓸 때 씁니다.

  ```
  !TD 보고서 제출 /* 3장부터 다시 검토 */ 금요일까지
  ```

- 한 줄에 여러 번 열어도 됩니다. 각 덩어리가 메모의 한 줄이 됩니다.
- `/*` 는 링크와 겹치지 않으므로 `https://example.com/a//b` 는 어디에 있든 안전합니다.
- 여는·닫는 기호는 `settings.json` 의 `Routing.NoteOpen` / `Routing.NoteClose` 에서 바꿀 수 있습니다.

반복 할일은 체크해도 완료되지 않고 **다음 차례로 넘어갑니다**. `매일 오전 7시 스트레칭` 을 체크하면 내일 7시로 옮겨갑니다.

### 3.6 붙여 쓰는 예

```
!CD 매주 화요일 오전 10시 주간회의 #팀 30분 전 알림
8월 10일 ~ 8월 12일 워크샵 !CD
!TD !1 금요일까지 분기 보고서 제출 #업무
!TM 내일 오후 3시부터 4시까지 기획 리뷰 @홍길동 @kim@corp.com
```

## 4. 단축키

| 키 | 하는 일 |
|---|---|
| `Ctrl` + `Alt` + `Space` | 어디서든 빠른 입력창 열기 |
| `Ctrl` + `Alt` + `D` | 위젯 표시 / 숨기기 |
| `Ctrl` + `Alt` + `C` | 누적 **일정** 목록 열기 / 닫기 |
| `Ctrl` + `Alt` + `T` | 누적 **할일** 목록 열기 / 닫기 |

빠른 입력창 안에서:

| 키 | 하는 일 |
|---|---|
| `Enter` | 저장하고 닫기 |
| `Esc` | 닫기 (다른 곳을 클릭해도 닫힘) |
| `Ctrl` + `1` | 이번 건만 할일로 |
| `Ctrl` + `2` | 이번 건만 일정으로 |
| `Ctrl` + `3` | 이번 건만 양쪽 모두 |
| `Ctrl` + `O` | 이번 건만 Outlook 전송 켜기 / 끄기 |
| `Ctrl` + `M` | 이번 건만 Teams 회의 폼 열기 켜기 / 끄기 |

`Ctrl`+`1`/`2`/`3` 은 **같은 키를 한 번 더 누르면 풀립니다** — 기본 분류로 되돌아갑니다. `Ctrl`+`O` 와 `Ctrl`+`M` 은 다른 축이라 분류와 따로 놉니다.

네 단축키 모두 **설정에서 바꿀 수 있습니다.** 설정 창의 단축키 칸을 클릭하고 원하는 조합을 그대로 누르면 됩니다. 다른 프로그램이 이미 쓰고 있는 조합이면 그 자리에서 알려줍니다.

입력창은 타이핑하는 동안 **해석 결과를 그대로 보여줍니다** — 어디에 저장될지, 제목이 뭐가 될지, 언제로 잡혔는지. 저장하기 전에 확인하고 고칠 수 있습니다.

## 5. 바탕화면 위젯

- **표시 방식** 3가지 (설정에서 선택)
  - `바탕화면` (기본): 다른 창 뒤에 머무릅니다. Alt+Tab과 작업 표시줄에도 안 나옵니다. 클릭해서 입력할 때만 앞으로 나옵니다.
  - `항상 위`: 모든 창 위에 뜹니다.
  - `일반`: 보통 창처럼 동작합니다.
- **이동**: 위쪽 날짜 영역을 잡고 끌면 됩니다. 위치는 자동 저장됩니다.
- **크기**: 오른쪽 아래 모서리를 끌면 조절됩니다. 가로와 세로가 **각각 따로** 움직입니다.
  - **가로 300~440 px** — 달력의 비율을 정하는 축입니다. 날짜 칸은 정사각형으로 폭을 따라가므로 폭을 키우면 달력이 커지고 아래 구분선도 함께 내려갑니다. 글자 크기도 칸에 맞춰 조정됩니다. 이 범위 밖으로는 형태가 무너져서 제한을 뒀습니다.
  - **세로 ~1000 px** — 달력에는 전혀 영향을 주지 않습니다. **늘린 만큼 전부 일정/할일 목록이 길어집니다.** 항목이 많으면 세로만 늘리면 됩니다. 최소 높이는 달력이 잘리지 않는 선(목록 3줄 정도)에서 폭에 따라 자동으로 정해집니다.
- **불투명도**: 60 / 80 / 92 / 100 %
- 달력의 날짜 아래 점은 그날 **일정(진한 점)** 과 **할일(연한 점)** 이 있다는 표시입니다.
- **오늘을 선택하면 지난 할일도 같이 나옵니다.** 미완료 할일이 날짜가 지났다고 사라지면 그대로 잊히기 때문입니다. 이런 항목은 날짜가 굵게, 그리고 원래 날짜까지 함께 표시되어 오늘 것과 구분됩니다. 다른 날짜를 선택하면 그날 항목만 나옵니다.
- 아래쪽 입력칸은 빠른 입력창과 똑같은 문법을 씁니다.
- **줄을 더블클릭하면 편집 창**이 뜹니다 — 제목 · 메모 · 날짜 · 알림 · 태그 · 우선순위를 고칠 수 있습니다. [7. 항목 편집](#7-항목-편집)

### 달력 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| **주 시작 요일** | 월 ~ 일 | `일 ~ 토` 로 바꿀 수 있습니다. 표시뿐 아니라 **`이번주` / `다음주` 해석에도 함께 적용**되어, "이번주 일요일"이 달력에 보이는 그 일요일을 가리킵니다. |
| **토요일 파랑 · 일요일 빨강** | 꺼짐 | 켜면 토/일의 요일 머리글과 날짜 숫자에 색이 들어갑니다. 꺼두면 주말도 회색조로만 구분됩니다. |

## 6. 누적 목록 창

위젯은 **선택한 하루**만 보여줍니다. 지금까지 쌓인 걸 전부 훑어보려면 별도 창을 씁니다. **일정과 할일이 각각 독립된 창**이고, 단축키로 열고 닫습니다.

- 열기/닫기: `Ctrl+Alt+C` (일정) · `Ctrl+Alt+T` (할일)
- 트레이 아이콘 우클릭 → **일정 목록** / **할일 목록**
- 위젯의 각 섹션 제목 옆 **"전체"** 버튼
- 창 안에서 `Esc` 를 누르면 닫힙니다

**날짜순으로 정렬되고, 날짜별로 묶여서** 표시됩니다. 각 날짜 머리글에는 그날의 건수가 붙고, 오늘 · 내일 · 모레 · 어제는 날짜 앞에 그렇게 표기됩니다.

```
어제 · 8월 6일 (목)      2
  ...
오늘 · 8월 7일 (금)      3
  ...
8월 12일 (수)           1
  ...
날짜 없음                4      ← 할일 창에만, 맨 아래
```

- **지난 날짜 그룹은 흐리게** 표시되어 오늘과 앞으로의 일에 눈이 먼저 갑니다.
- 목록 안에서도 **체크 · 삭제가 그대로** 됩니다. 위젯과 같은 데이터를 보고 있어서 한쪽에서 바꾸면 다른 쪽에 즉시 반영됩니다.
- 줄을 **더블클릭하면 편집 창**이 뜹니다. 위젯에서와 같습니다.
- 할일 창 상단의 **"완료 포함"** 을 켜면 이미 끝낸 항목도 같이 보입니다. 이 선택은 저장됩니다.
- 창 위치와 크기는 각각 따로 기억합니다.
- 날짜 없이 입력한 할일은 맨 아래 **"날짜 없음"** 그룹으로 모입니다.

### 태그로 걸러 보기

창 상단에 **지금 쓰이고 있는 태그가 건수와 함께 칩으로** 나옵니다. 많이 쓴 태그가 앞에 옵니다.

```
[전체]  [#업무 12]  [#보고 5]  [#개인 4]  [#팀 2]        [모두 포함]
```

- 칩을 누르면 필터가 걸리고, 다시 누르면 풀립니다. **여러 개 고를 수 있습니다.**
- **`모두 포함` / `하나라도`** 버튼으로 여러 태그를 골랐을 때의 의미를 바꿉니다.
  - `모두 포함`(기본): `#업무`+`#긴급` → 두 태그가 **다 붙은** 항목만. 좁혀 볼 때.
  - `하나라도`: `#업무`+`#개인` → 둘 중 **하나라도** 붙은 항목. 여러 영역을 같이 볼 때.
- 필터는 **날짜 그룹과 아래 반복 섹션에 함께** 적용되고, 상단 건수도 걸러진 개수로 바뀝니다.
- `전체` 를 누르면 해제됩니다.
- **창을 열 때마다 필터는 초기화됩니다.** 예전에 걸어둔 필터 때문에 항목이 안 보이는데 이유를 알 수 없는 상황을 막기 위해서입니다. (`모두 포함` / `하나라도` 선택은 유지됩니다.)

> 태그는 **한 항목에 여러 개** 달 수 있습니다. `내일 오후 3시 스프린트 리뷰 #업무 #팀 #보고` 처럼 그냥 이어 쓰면 됩니다. 대소문자는 구분하지 않아서 `#Work` 와 `#work` 는 같은 태그로 묶입니다.

### 반복 항목은 맨 아래 한 줄로

반복 일정·할일은 끝이 없어서 날짜별로 늘어놓으면 일반 항목이 묻힙니다. 그래서 **날짜 그룹에서 빼고 맨 아래 "반복 일정" / "반복 할일" 섹션에 규칙당 한 줄씩** 모읍니다.

```
반복 일정 / 반복 할일
  3분할 운동 - 상체  [매주 월,목]              다음 8월 10일
  주간회의          [매주 화]                 다음 8월 11일 10:00
  월세 이체         [매달 25일]               다음 8월 25일
  면허 갱신         [매년 3월 2일]            다음 2027년 3월 2일
  스탠드업          [평일]                    다음 8월 10일 09:00
  회식             [격주 목]                 다음 8월 20일
```

- 대괄호 안이 반복 주기입니다. 요일이 여럿이면 `[매주 월,목]` 처럼 붙습니다.
- 오른쪽에 **다음 차례 날짜**가 나옵니다.
- **반복 할일은 체크박스가 있습니다.** 체크하면 완료 처리되는 게 아니라 다음 차례로 넘어가고, 줄은 그대로 남은 채 "다음" 날짜만 바뀝니다.
- 삭제 버튼은 반복 규칙 자체를 지웁니다.

> 오늘 해야 할 반복 항목은 **위젯**에 그대로 나옵니다. 목록 창은 "무엇이 어떤 주기로 돌고 있는지"를 보는 곳이고, 위젯은 "오늘 뭘 해야 하는지"를 보는 곳입니다.

## 7. 항목 편집

이미 저장한 항목은 **줄을 더블클릭하면** 편집 창이 뜹니다. 위젯에서도, 누적 목록 창에서도 같습니다.

| 고칠 수 있는 것 | |
|---|---|
| **제목** | 창이 열리면 여기에 커서가 있고 전체가 선택되어 있습니다 |
| **메모** | 여러 줄 그대로. 여기서는 `\n` 대신 그냥 Enter 로 줄을 바꿉니다 |
| **날짜 · 시각** | `2026-08-12` / `14:30` 형식. 각각 체크로 끄고 켭니다 |
| **태그** | `#업무 #보고` — `#` 없이 띄어 써도 같습니다 |
| **알림** | 몇 분 전에 띄울지. 비우면 알림 없음 |
| **우선순위** | 할일에만 있습니다 |

- **일정은 날짜를 지울 수 없습니다.** 달력에 그릴 자리가 없어지기 때문입니다. 할일은 날짜를 끄면 "날짜 없음" 으로 내려갑니다 — 이때 알림도 같이 지워집니다. 없어진 날짜를 기준으로 잡힌 알림은 울릴 수가 없기 때문입니다.
- **일정의 길이는 유지됩니다.** 2시간짜리 회의를 다른 시각으로 옮겨도 2시간짜리 그대로입니다.
- 날짜 칸을 **비우는 것도 "날짜 없음"** 입니다. 체크를 끄는 것과 같습니다 (할일만).
- 날짜 칸에 해석할 수 없는 걸 쓰면 **저장을 거부하고 알려줍니다.** 조용히 엉뚱한 날로 옮기지 않기 위해서입니다.
- `Esc` 로 취소, `Ctrl`+`Enter` 로 저장. 메모칸에서도 `Ctrl`+`Enter` 는 저장입니다.
- 편집 창의 **삭제**는 목록에서 지우는 것과 같습니다.

> 편집한 내용은 **Outlook으로 다시 보내지지 않습니다.** `!OL` 로 보낸 항목을 여기서 고쳐도 Outlook 쪽 원본은 그대로입니다. 지금 연동은 한 번 보내는 단방향입니다.

## 8. Outlook 연동

로컬에 설치된 **Outlook에 항목을 복사**합니다. 자연어로 한 줄 치면 회사 캘린더/작업에 그대로 들어가고, Outlook이 서버로 올려주니 **휴대폰 Outlook에도 따라옵니다.**

**지금은 보내기 전용(push)입니다.** Flowdeck이 Outlook에 쓰기만 하고 읽어오지는 않습니다. 그래서 충돌이 생길 여지가 없습니다.

### Outlook을 안 쓴다면 — 아무것도 안 해도 됩니다

**Outlook이 깔려 있지 않은 PC에서는 이 기능이 아예 보이지 않습니다.** 설정 창의 "Outlook 연동" 항목 자체가 뜨지 않고, 앱은 설치 직후부터 완전히 로컬 전용으로 동작합니다. 별도 버전을 받을 필요도, 뭘 끌 필요도 없습니다.

Outlook은 깔려 있지만 Flowdeck이 건드리지 않았으면 할 때는 **설정 → Outlook 연동 → "Outlook 연동 사용"** 을 끄면 됩니다. `!OL` 을 포함해 밖으로 나가는 동작이 전부 멈춥니다.

> 회사 PC와 개인 노트북에서 같은 실행 파일을 그대로 쓰면 됩니다. 설정은 PC마다 따로 저장되고, Outlook 유무는 **실행할 때 알아서 판단**합니다.

### 왜 COM인가

Graph API가 아니라 **로컬 Outlook을 COM으로 직접** 조작합니다. 이유는 하나입니다 — **아무 승인도 필요 없습니다.**

| | Graph API | COM (지금 방식) |
|---|---|---|
| Entra 앱 등록 | 필요 | **불필요** |
| 관리자 동의 | 필요 | **불필요** |
| 네트워크 허용 | 필요 | **불필요** |
| 조건부 액세스 | 걸림 | **해당 없음** |

로그인한 사용자 권한으로, 이미 동기화돼 있는 로컬 데이터만 건드립니다. 망분리 환경에서 통과될 확률이 압도적으로 높은 경로입니다.

Office 인터롭 어셈블리에 링크하지 않고 **런타임 바인딩**으로 붙기 때문에, Outlook 버전을 가리지 않고 **Outlook이 없는 PC에서는 그냥 "없음"으로 보고**하고 넘어갑니다.

### 쓰는 법

```
!OL  내일 오후 3시 팀 회의        → 로컬 + Outlook (분류는 기본 규칙대로)
!CD !OL  내일 오후 3시 팀 회의     → Outlook 캘린더에 약속으로
!TD !OL  금요일까지 보고서 제출     → Outlook 작업으로
```

- `!OL` · `!outlook` · `!아웃룩` — 이 항목을 Outlook에도 보냅니다
- `!NOL` · `!local` · `!로컬` — 이 항목만 보내지 않습니다

**표기 순서는 상관없습니다.** `!CD !OL` 이든 `!OL !CD` 든 같습니다.

**매번 치기 번거로우면** 설정 → Outlook 연동 → "새 항목을 Outlook에도 저장"을 켜세요. 그 뒤로는 전부 자동으로 가고, 특정 항목만 빼고 싶을 때 `!NOL` 을 붙이면 됩니다.

빠른 입력창에서 **`→ Outlook` 칩**이 뜨면 이번 항목이 전송된다는 뜻입니다.

### 넘어가는 것

| Flowdeck | Outlook |
|---|---|
| 제목 | 제목 |
| 시작·종료 시각, 종일 여부 | 그대로 |
| 반복 (매일·평일·매주 요일·격주·매월·매년) | Outlook 반복 패턴으로 변환 |
| 알림 (N분 전) | 미리 알림 |
| 태그 | 범주(Categories) |
| 우선순위 | 작업 중요도 |
| 원본 입력 문장 | 본문에 `[Flowdeck] ...` 로 기록 |

Outlook 작업은 **시각 없이 날짜만** 가집니다(Outlook 자체 제약). 시각은 미리 알림에 남습니다.

### 알아두실 것

- **저장은 항상 로컬이 먼저입니다.** Outlook이 꺼져 있거나 오류가 나도 **입력한 항목은 절대 사라지지 않고**, 트레이 알림으로 "Outlook 저장 실패 (항목은 저장되었습니다)" 라고 알려줍니다.
- Outlook이 실행 중이 아니면 첫 전송 때 Outlook이 뜨면서 몇 초 걸릴 수 있습니다. 이 작업은 **별도 스레드에서 처리해서 위젯이 멈추지 않습니다.**
- **알림이 두 번 올 수 있습니다.** Outlook 미리 알림과 Flowdeck 트레이 알림이 각각 뜨므로, 한쪽은 쓰지 않는 편이 낫습니다.
- 전송은 **새로 입력할 때 한 번**입니다. 나중에 Flowdeck에서 고쳐도 Outlook 쪽은 따라 바뀌지 않습니다.

### 나중에 읽기까지 하려면

`IExternalStore` 인터페이스 뒤에 구현이 들어가 있고, 저장된 항목마다 **`ExternalLink`(어느 시스템의 어떤 ID인지)를 이미 기록**해 둡니다. 읽기 모드를 붙일 때 이게 대조 기준이 되어 **중복 생성을 막아줍니다.** 읽기용 인터페이스만 추가하고 같은 클래스가 구현하면 됩니다.

Graph API로 가더라도 같은 인터페이스에 구현체 하나만 더 만들면 되고, 나머지 코드는 그대로입니다.

읽기를 붙일 때 **지금 기능과 부딪히는 지점**은 미리 정리해 두었습니다.

| 지점 | 판정 | 근거 |
|---|---|---|
| 기본 분류 vs 읽어온 항목 | **충돌 없음** | Outlook 약속은 일정, Outlook 작업은 할일로 **확정**입니다. 읽어온 항목은 파서를 타지 않으므로 기본 분류가 끼어들 자리가 없습니다. |
| "항상 저장" vs 읽기 = 무한 증식 | **막아둠** | 이미 `ExternalLink` 가 붙은 항목은 다시 보내지 않습니다. 이 방어가 없으면 읽어온 항목을 되쏘고, 그게 또 읽히면서 읽을 때마다 복제됩니다. |
| `!NOL` 항목 | **충돌 없음** | 링크가 없으니 읽기 쪽에서 건드릴 대상이 아닙니다. 계속 로컬로 남습니다. |
| 기본 분류 `둘 다` + 읽기 | **주의** | 한 줄이 일정 1 + 할일 1로 갈라져 Outlook에도 둘로 들어갑니다. 이후 Outlook에서 약속만 고치면 **할일 쪽은 따라오지 않습니다.** 둘로 나뉜 순간부터 서로 남남입니다. |
| 로컬에서 삭제 | **현재 한계** | Outlook 쪽은 남습니다. "항상 저장"을 켜두면 이 차이가 눈에 띄게 쌓이니, 읽기를 붙일 때 삭제 동기화도 같이 정해야 합니다. |

## 9. Teams 회의 잡기

한 줄로 회의를 **잡되, 보내지는 않습니다.** `!TM` 을 붙이면 Teams의 새 회의 창이 제목·시간·참석자까지 채워진 채로 열리고, **최종 저장 버튼은 사용자가 누릅니다.**

```
!TM 내일 오후 3시부터 4시까지 기획 리뷰 @홍길동 @kim@corp.com
```

- 표기: `!TM` · `!teams` · `!팀즈` (빠른 입력창에서는 `Ctrl`+`M`)
- **로컬에도 그대로 저장됩니다.** Teams 창에서 그냥 닫아도 Flowdeck에 친 내용은 남습니다.

### 왜 자동 생성이 아니라 폼을 여는가

회의를 코드로 곧장 만들려면 Graph API가 필요하고 — 앱 등록, 위임 권한, 관리자 승인 — **그리고 잘못 해석된 회의가 그대로 발송됩니다.** 참석자 전원에게요.

딥링크는 **URL 하나**입니다. 권한도 등록도 승인도 필요 없어서 지금 당장 되고, 무엇보다 파싱이 틀렸을 때 치르는 값이 "닫기 한 번"입니다. 회의 소집은 되돌리기가 비싼 동작이라 이쪽이 맞습니다.

### 참석자 지정

| 쓰는 법 | 결과 |
|---|---|
| `@hong@corp.com` 또는 `hong@corp.com` | 주소 그대로 |
| `@홍길동` | 주소록에서 찾아 변환 |
| `@모르는이름` | **제목에 그대로 남습니다** (지워지지 않음) |

주소록은 **설정 → Teams 회의 → 주소록 편집** 에서 관리합니다. 이름과 메일 주소를 넣고 `추가`(또는 Enter), 지울 땐 줄 오른쪽 × 버튼. **저장 버튼은 없습니다** — 고치는 즉시 반영되고, 창을 닫아도 잃을 게 없습니다.

이름 규칙 하나만 지키면 됩니다. **공백을 쓸 수 없습니다.** `@김 대리` 는 공백에서 끊기기 때문에, 이런 이름은 등록해봐야 영영 안 불립니다. 그래서 편집기가 아예 안 받습니다.

> 회사 주소록을 자동으로 읽어오지는 않습니다. 그러려면 결국 Graph 권한이 필요해서, 이 경로를 고른 이유 자체가 없어집니다.

파일을 직접 고쳐도 됩니다. `%APPDATA%\Flowdeck\settings.json`:

```json
"Contacts": {
  "Aliases": {
    "홍길동": "hong@corp.com",
    "김대리": "kim@corp.com"
  }
}
```

> **참석자 추출은 `!TM` 이 있을 때만 일어납니다.** `hong@corp.com 에게 회신` 같은 평범한 할일에서 주소가 제목에서 사라지면 곤란하니까요.

### 알아두실 것

- **시각을 안 쓰면 시각 칸은 비워둡니다.** `!TM 8월 12일 워크샵` 처럼 종일이면 임의로 시간을 찍지 않습니다. 채워진 것처럼 보이는데 틀린 폼이 빈 칸보다 나쁩니다.
- **`!TM` 은 자동 Outlook 전송을 끕니다.** Teams가 저장할 때 Outlook 캘린더에 알아서 넣기 때문에, "항상 저장"이 켜져 있으면 같은 자리가 두 번 잡힙니다. `!OL` 을 직접 치면 그건 그대로 존중합니다.
- 원본 입력 문장이 회의 본문에 `[Flowdeck] ...` 로 들어갑니다. 폼에서 "내가 뭐라고 쳤더라"를 확인할 수 있습니다.
- Teams 앱이 없으면 브라우저 Teams로 열립니다.

### 나중에 Graph가 열리면

`TeamsDeepLink` 는 URL만 만드는 순수 함수라, 실제 회의 생성(`onlineMeeting`)으로 바꾸더라도 파서·저장·UI는 손댈 필요가 없습니다. 다만 **바꿀지 말지는 별개 문제입니다** — 위에 적은 이유로, 폼을 여는 쪽이 계속 나을 수 있습니다.

## 10. 두 PC 사이로 항목 옮기기

망이 갈린 환경을 위한 **단방향 반입 통로**입니다. 밖에서 떠오른 아이디어를 파일로 내보내서 업무 PC에 들여놓는 용도예요.

```
개인 노트북 ──(파일 하나)──▶ 업무 PC
```

### 내보내기 — 목록 창에서

`Ctrl+Alt+C` (일정) 또는 `Ctrl+Alt+T` (할일) 로 목록 창을 열고, 오른쪽 위 **내보내기 버튼**을 누릅니다.

**지금 화면에 보이는 것이 그대로 파일이 됩니다.** 태그 칩으로 목록을 좁혀두면 좁혀진 만큼만 나갑니다 — 별도의 "항목 선택" 화면이 없는 게 의도입니다. 보고 있는 것과 내보내는 것이 어긋날 여지를 안 만들려고요.

일정과 할일은 창이 따로라 파일도 따로 나옵니다. 둘 다 필요하면 두 번 내보내면 되고, 가져오기는 어느 쪽이든 받습니다.

### 가져오기 — 설정에서

**설정 → 자료 주고받기 → 파일에서 가져오기**

### 규칙

| | |
|---|---|
| **더하기만 합니다** | 이미 있는 항목을 고치거나 지우지 않습니다. 잘못된 파일을 넣어도 최악이 "필요 없는 항목이 늘어남" 입니다 |
| **같은 파일을 두 번 넣어도 안전** | 항목 ID로 구분해서 이미 있으면 건너뜁니다. "3건 가져왔습니다. 2건은 이미 있어 건너뛰었습니다" 처럼 알려줍니다 |
| **업무 PC에서 고친 내용이 안 덮입니다** | 들여온 뒤 제목을 다듬었는데 같은 파일을 또 넣어도 다듬은 게 유지됩니다 |
| **Outlook 연결 정보는 안 따라갑니다** | 저쪽 Outlook의 항목 ID라 여기선 의미가 없습니다. 그대로 왔으면 "이미 보냈다"고 표시돼서 **영영 안 보내지는** 항목이 됩니다 |

### 형식

`.ics` 가 아니라 **Flowdeck 자체 형식(JSON)** 입니다. `.ics` 는 일정은 잘 담지만 할일은 부실해서, 태그·우선순위·반복·원본 입력 문장이 다 날아갑니다.

확장자는 **`.txt`** 입니다. 사내 메신저가 `.json` 이나 `.csv` 는 이유도 없이 막고 텍스트 파일은 통과시키기 때문입니다. 아무리 잘 만든 파일도 보낼 수 없으면 소용이 없죠.

그래서 파일 위쪽은 **사람이 읽는 부분**입니다. 메신저에서 미리보기만 해도 뭐가 들어있는지 보입니다.

```
Flowdeck 내보내기 · 2026-08-10 21:00 · 3건

- [할일] 보고서 제출 · 8월 12일 15:00 #업무
- [일정] 팀 회의 · 8월 11일 15:00

--- 여기서부터는 앱이 읽는 부분입니다. 지우지 마세요 ---
{ "Format": "flowdeck.transfer", "Version": 1, ... }
```

위쪽 설명은 마음대로 고쳐도 됩니다 — 앱은 구분선 아래만 읽습니다. 예전에 `.json` 으로 내보낸 파일도 그대로 가져와집니다.

Flowdeck 파일이 아니거나 더 새로운 버전이면 **한 줄로 이유를 알려주고 아무것도 하지 않습니다.**

> **반출입 규정은 확인하세요.** 들이는 방향이라 보통 통제가 덜하지만, 사내 규정은 환경마다 다릅니다.

## 11. 데이터

전부 로컬에 평문 JSON으로 저장됩니다. 계정도 서버도 없습니다.

```
%APPDATA%\Flowdeck\
  workspace.json     할일과 일정
  workspace.json.bak 직전 저장본
  settings.json      환경설정
  crash.log          오류 기록 (문제가 있을 때만 생김)
```

문제가 생기면 `crash.log` 를 먼저 보세요. 오류가 나도 앱은 계속 돌아가고, 트레이에 알림이 뜨면서 자세한 내용이 이 파일에 쌓입니다.

저장은 임시 파일에 쓴 뒤 바꿔치기하는 방식이라, 저장 도중에 꺼져도 이전 파일이 깨지지 않습니다.

**백업**은 이 폴더를 통째로 복사하면 됩니다 (설정 → "데이터 폴더 열기").

**휴대폰으로 옮기려면** 설정 → "일정 .ics 내보내기" 로 iCalendar 파일을 만든 뒤 구글 캘린더나 Outlook에 가져오기 하면 됩니다. 반복 규칙과 알림도 같이 넘어갑니다.

## 14. 안드로이드 / 아이폰으로 확장하기

`Flowdeck.Core` 는 이미 이걸 염두에 두고 짜여 있습니다. 플랫폼 API를 하나도 쓰지 않고, 시각도 `DateTime.Now` 를 직접 부르는 대신 전부 인자로 받습니다.

1. `dotnet new maui -n Flowdeck.Mobile` 후 `Flowdeck.Core` 를 참조 — **파서 · 분류 · 반복 · 저장 로직이 그대로 동작합니다.**
2. 화면만 MAUI XAML로 새로 그립니다. `WidgetViewModel` / `QuickAddViewModel` 은 WPF 타입을 안 쓰므로 `ICommand` 정도만 바꾸면 대부분 재사용됩니다.
3. 저장 위치는 `IWorkspaceStore` 구현만 갈아끼우면 됩니다. 기기 간 동기화가 필요하면 이 인터페이스 뒤에서 처리하면 되고, 나머지 코드는 건드릴 필요가 없습니다.
4. 안드로이드 홈 화면 위젯과 iOS 위젯 익스텐션은 각 플랫폼 고유 작업이지만, 표시할 데이터는 같은 `WorkspaceRepository` 에서 가져옵니다.
5. **Teams 회의(`!TM`)는 모바일에서 뺄 수 있습니다.** 표기 목록이 설정값이라 `Routing.TeamsMarkers` 를 비우면 그대로 없는 기능이 됩니다. `TeamsDeepLink` 자체는 URL 문자열만 만들고 여는 건 셸이 하므로, 안 열면 그만입니다 — 코드를 갈래로 나눌 필요가 없습니다.

동기화가 필요하면 [10. 두 PC 사이로 항목 옮기기](#10-두-pc-사이로-항목-옮기기)의 파일 형식(`TransferFile`)이 그대로 쓰입니다. 단방향·추가 전용이라 병합·삭제 전파·시계 문제를 전부 비껴가고, 클라우드에 올릴 때도 같은 파일 하나면 됩니다.

이 저장소의 `android/` 폴더에는 같은 아이디어를 Todoist·구글 캘린더와 연동해 구현한 별개의 안드로이드 앱(TaskBridge)이 이미 있습니다. 참고용으로 쓸 수 있습니다.
