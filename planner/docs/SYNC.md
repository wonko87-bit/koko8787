# 동기화 설계 — 노트북 ↔ 태블릿 (Google 드라이브)

> 상태: **설계 확정, 구현 전**. 개인용 빌드(노트북·태블릿)에만 켜고, 회사 PC 빌드는 지금처럼 로컬 파일만 씁니다.

## 1. 방향

각 기기는 지금처럼 **자기 로컬 파일을 원본처럼** 쓰고, 사용자의 Google 드라이브 **앱 전용 숨김 공간
(appDataFolder)** 에 있는 공유본과 주기적으로 **칸 단위로 합칩니다**.

- 권한은 `https://www.googleapis.com/auth/drive.appdata` 하나뿐입니다. Google 분류로 *권장 · 민감하지 않음*이라
  검수 없이 "프로덕션" 게시가 가능하고, 이 앱이 만든 숨김 파일 외에는 드라이브의 어떤 파일도 볼 수 없습니다.
- 인터넷이 없어도 그대로 쓰고, 연결되면 합칩니다. 서버는 따로 두지 않습니다.

## 2. 왜 "칸 단위 병합"인가

파일을 통째로 덮어쓰면, 노트북에서 화요일을 고치고 태블릿에서 목요일을 고친 경우 한쪽 수정이 사라집니다.
그래서 데이터를 잘게 나눈 **칸(셀)** 마다 마지막 수정 시각을 붙이고, 합칠 때 칸마다 더 최근 것을 고릅니다
(Last-Writer-Wins 맵). 두 기기가 같은 칸을 고쳤을 때만 나중 것이 이기고, 다른 칸은 모두 살아남습니다.

### 칸의 단위

| 경로 | 예 | 비고 |
|---|---|---|
| `days/<날짜>/<줄>` | `days/2026-11-19/3` | 할일 한 줄 (상태·시간·내용·구분·이월정보 전체가 한 칸) |
| `weeks/<목요일>/goals/<n>` | `weeks/2026-11-19/goals/0` | 주 목표 한 줄 |
| `weeks/<목요일>/memo` | | 주간 메모 |
| `weeks/<목요일>/next/<줄>` | | 다음 주로 넘길 일 한 줄 |
| `months/<YYYY-MM>/goals/<n>` · `todos/<줄>` | | 월간 목표·할일 |
| `settings/customHolidays/<날짜>` | | 사용자 휴일 |
| `settings/weekStart` | | (테마·화면 배율은 기기별이라 동기화하지 않음) |

### 칸에 붙는 정보

```json
{ "v": { "x": "보고서 초안", "t": "09:30", "s": "done", "c": "업무" },
  "u": 1763512345678,      // 수정 시각 (ms, 기기 시계)
  "d": "laptop-3f9a" }     // 수정한 기기 ID (시각이 같을 때 비교용)
```

- **지우기도 수정입니다**: 내용을 지우면 `v: null`인 칸(묘비)을 남겨, 다른 기기의 옛 내용이 되살아나지 않게 합니다.
  묘비는 90일 뒤 정리합니다.
- **시계 어긋남**: 기기 시계가 몇 분 틀려도 "같은 칸을 몇 분 안에 양쪽에서 고친" 경우에만 영향이 있어 개인용으론 충분합니다.
  저장할 때 `u = max(지금, 그 칸의 기존 u + 1)` 로 두어 시계가 뒤로 가도 수정이 묻히지 않게 합니다.

## 3. 동기화 흐름

```
[기기]  로컬 파일 ──(칸 단위 병합)──▶ 병합본 ──▶ 로컬 저장
            ▲                          │
            └──── 드라이브 공유본 ◀─────┘ (업로드)
```

1. 드라이브 appDataFolder에서 `planner-sync.json` 을 받는다 (없으면 만든다).
2. 로컬 칸들과 칸 단위로 합친다.
3. 합친 결과를 로컬에 저장하고 화면을 갱신한다 (입력 중인 칸은 건드리지 않는다).
4. 로컬에만 있던 변경이 있었다면 공유본을 업로드한다.

- **언제**: 앱을 열 때 · 트레이에서 다시 띄울 때 · 마지막 수정 5초 뒤 · 화면이 보이는 동안 5분마다.
- **동시에 올린 경우**: 드라이브는 조건부 덮어쓰기가 없어 두 기기가 같은 순간에 올리면 한쪽 업로드가 덮일 수 있습니다.
  하지만 덮인 쪽도 자기 로컬에 최신 칸을 그대로 갖고 있어서 **다음 동기화 때 다시 합쳐 올라갑니다** (결국 같은 상태로 수렴).
- 상단 바에 동기화 상태(완료 시각 / 진행 중 / 오프라인 / 로그인 필요)를 작게 표시합니다.

## 4. 로그인 (OAuth 2.0 + PKCE)

저장소에 이미 있는 TaskBridge와 같은 방식, 곧 **GitHub Pages 중계 페이지**를 씁니다.

```
앱 ──(브라우저로 Google 로그인 열기, state에 돌아갈 곳 표시)──▶ Google
Google ──▶ https://wonko87-bit.github.io/koko8787/auth/planner/callback/?code=…&state=…
중계 페이지 ──▶ 데스크톱:  http://127.0.0.1:<포트>/?code=…   (앱이 잠깐 띄운 로컬 수신기)
            └─▶ 태블릿:   planner://auth?code=…              (딥링크)
앱 ──(code + PKCE verifier로 토큰 교환)──▶ refresh token을 기기에 저장
```

- OAuth 클라이언트 ID·시크릿은 **저장소에 넣지 않고** GitHub 저장소 시크릿에서 빌드할 때만 주입합니다
  (`PLANNER_GOOGLE_CLIENT_ID`, `PLANNER_GOOGLE_CLIENT_SECRET`). 시크릿 없이 빌드하면 동기화 기능이 아예 숨겨집니다.
  회사 PC용 빌드는 이 방식으로 만듭니다.
- refresh token은 기기 안에만 저장합니다 (Windows: 자격 증명 관리자, 안드로이드: 앱 전용 저장소).

## 5. 사용자가 해 줄 일 (Google Cloud 콘솔, 1회)

TaskBridge용 프로젝트와 **분리된 새 프로젝트**를 권장합니다. 캘린더처럼 민감한 권한이 섞인 프로젝트는 "프로덕션"
게시에 검수가 필요해서, 테스트 상태로 두면 로그인이 **7일마다 풀립니다**.

1. Google Cloud 콘솔 → 새 프로젝트 `Planner`
2. API 및 서비스 → 라이브러리 → **Google Drive API** 사용 설정
3. OAuth 동의 화면 → 외부 → 앱 이름 `Planner`, 범위에 `.../auth/drive.appdata` 추가 → **앱 게시(프로덕션)**
4. 사용자 인증 정보 → OAuth 클라이언트 ID → **웹 애플리케이션**
   → 승인된 리디렉션 URI: `https://wonko87-bit.github.io/koko8787/auth/planner/callback/`
5. GitHub 저장소 → Settings → Secrets and variables → Actions 에
   `PLANNER_GOOGLE_CLIENT_ID`, `PLANNER_GOOGLE_CLIENT_SECRET` 등록
